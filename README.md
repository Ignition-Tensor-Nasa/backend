# PSI-Lens API

FastAPI backend of a NASA combustion-data explorer: search a small curated
catalogue of real ACME CFI-G test runs by filters, open a run, and load its
measurements as JSON for charts. An assistant can turn a Polish/English description into
the same filters.

## Project structure

```text
app/
  main.py                # App, CORS, error handlers, router registration
  routes/                # REST endpoints (hello, filters, cases, datasets)
  services/catalogue.py  # Curated catalogue, filter validation and search (Polars)
  ai/interpret.py        # Description -> validated filters (live or demo)
  ai/provider.py         # Schema-constrained provider adapters
data_prep/
  prepare.py             # Builds data/curated/ from raw NASA files (run this)
  manifest.json          # Hand-reviewed list of selected tests
  flex.py                # CFI (FLEX) droplet adapter and D² fit
  similarity.py          # Nearest-neighbour artifact
  research_context.json  # Reviewed research-context tags with evidence
  two_pass.py            # Vocabulary proposal + classification check
  enrich_pdf.py          # Offline PDF metadata proposals for review
data/curated/            # Generated by data_prep: catalogue + measurement Parquet (git-ignored)
tests/                   # pytest checks on synthetic fixtures + real-data smoke test
polars_analysis/         # Earlier standalone analysis, not used by the API
```

## Run locally

Requires Python 3.10 or newer.

Choose one of the following setups from the project directory.

### Using a virtual environment

```sh
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
```

### Using globally installed libraries

If FastAPI, Uvicorn, Polars, httpx, jsonschema, python-dotenv and the Anthropic SDK are already installed for your Python interpreter
in versions compatible with `requirements.txt`, no installation is needed.

### Start the server

With either setup, run:

```sh
python3 -m uvicorn app.main:app --reload
```

Optional settings are listed in `.env.example`. Copy it to `.env` and edit it:
AI settings are read automatically from the backend's `.env`; for other settings
such as `CORS_ORIGINS` and `PSI_CURATED_DIR`, load it before starting with
`set -a; . ./.env; set +a`. The server starts without any of them or an LLM key.

Visit <http://127.0.0.1:8000/> or run:

```sh
curl http://127.0.0.1:8000/
```

The response is `{"message":"Hello, world!"}`. Interactive API documentation is
available at <http://127.0.0.1:8000/docs>.

## Prepare the demo data (B01)

The API serves a small curated slice of NASA PSI data. Build it once (and again
after editing the manifest); raw files are only read:

```sh
python3 -m data_prep.prepare --data-dir ../data_nasa
```

`--data-dir` is the folder containing `ACME-CFI-G_PSI-159/` and `CFI_PSI-39/`
(the FLEX adapter also needs `openpyxl`, see `polars_analysis/requirements.txt`).
The script reads
the hand-reviewed test list in `data_prep/manifest.json` and writes
`data/curated/` (git-ignored, replaced on every run):

- `catalogue.parquet`: one row per case (verified run) with filter values,
  source reference and note.
- `datasets.json`: descriptor of each dataset (columns, units, default axes,
  sampling/quality note).
- `parquet/<dataset_id>.parquet`: the measurements, full rate, parsed and
  normalised. The running backend reads only these files; if they are missing
  it answers 503 and never falls back to raw CSVs.
- `events.json`, `neighbors.json`, `context.json`: optional artifacts (B13,
  B11, B14).

What is and is not verified:

- A case is linked to its recording by the `Test Point:` field inside the raw
  file's preamble, checked against the ID in the experimental summary table.
  Tests with a missing, ambiguous or corrupted (NUL bytes) recording are skipped.
- Only ACME CFI-G normal flames are curated, so `o2_pct` always means the
  chamber O₂ mole fraction before the test. `pressure_kpa` is the table's
  approximate pressure, bar × 100.
- `time_s` is seconds since the first sensor sample (both datasets of a case
  share that zero). Source timestamps can jitter by a few milliseconds (one
  known 2 ms backward step in 21174F1); the API returns rows ordered by time. Sensor channels keep their raw recorded values with a null
  unit: the source files do not state units. Setpoints are volts, as named in
  the source header.
- `fuel` is the base hydrocarbon; the table's label (e.g. "30% butane") stays
  in the title and the fuel mole fraction in the note.

### Second source family: CFI droplet tests (B07)

`data_prep/flex.py` adds 14 CFI (FLEX) droplet tests through the same
case/dataset interface (`investigation = "CFI (FLEX)"`, case IDs `FLEX-nnnn`),
each with three datasets: droplet diameter, cool-flame diameter and radiometer
power, in the units named by the source columns.

- Link: the FLEX number in the file name, the Master Sheet row and the
  per-test summary PDF; the CIR run ID must match between sheet and PDF.
- `o2_pct` comes from the Master Sheet and is used only when the summary PDF
  agrees; FLEX-1213 disagrees (0.17 vs 0.210) and stays `null`.
- `pressure_kpa` is the sheet's nominal pressure, atm × 101.325. The PDF's
  measured pressure is quoted in the note.
- Each dataset keeps its own source time column (not a shared zero).
- Other families are not adapted; each would be a separate task.

## Filter options (B02)

`GET /api/v1/filters` returns the categories and known numeric bounds present
in the curated catalogue (`null` bounds when no case has that value):

```json
{"investigation": ["ACME CFI-G", "CFI (FLEX)"],
 "fuel": ["butane", "dodecane", "ethane", "propane"],
 "o2_pct": {"min": 17.0, "max": 39.655},
 "pressure_kpa": {"min": 50.663, "max": 506.625}}
```

### Extra filter: stoichiometric mixture fraction (B10)

`z_st` is a numeric range filter (0 to 1, no unit) on the `Zst` column of the
ACME CFI-G experimental table, used as tabulated. Droplet (FLEX) cases have no
such value, so any active `z_st` constraint excludes them. Example: the four
runs with the highest tabulated Zst, `{"filters": {"z_st": {"min": 0.25}}}`. It is part of
`FilterOptions`, `CaseSummary`, search validation and the assistant's schema.

## Case search (B03)

`POST /api/v1/cases/search` filters the curated case catalogue and returns
`{ "items": CaseSummary[], "total": number }`, ordered by case ID.

```sh
curl -X POST http://127.0.0.1:8000/api/v1/cases/search \
  -H 'Content-Type: application/json' \
  -d '{"filters": {"fuel": ["methane"], "o2_pct": {"min": 21}}}'
```

The catalogue is read once from `data/curated/catalogue.parquet` (folder
overridable with `PSI_CURATED_DIR`). Until it exists the endpoint answers 503.
Invalid keys, categories or ranges answer 422.

Tests (need `pytest` and `httpx`): `python3 -m pytest tests -q`. They use
synthetic fixtures and never call the AI provider; `tests/test_real_data.py`
runs only when `data/curated/` exists.

## Case detail (B04)

`GET /api/v1/cases/{case_id}` returns the case summary plus `source_label`,
`source_url` (null: no verified link), a curated `note` and the descriptors of
its datasets: `dataset_id`, `label`, `columns` (`key`, `label`, `data_type`,
`unit`), `default_x`, `default_y`. Unknown cases answer 404.

```sh
curl http://127.0.0.1:8000/api/v1/cases/CFIG-21291C1
```

## Dataset data for charts

`GET /api/v1/datasets/{dataset_id}/data` returns `application/json`:

```ts
type DatasetData = {
  dataset: Dataset;                      // same descriptor as in CaseDetail
  rows: (number | string | null)[][];    // one value per dataset.columns entry, same order
  note: string | null;                   // sampling / quality remarks
};
```

- Read from the prepared Parquet of an allowlisted dataset ID; the request
  never supplies a path. Unknown IDs answer 404, missing prepared data 503.
- Rows are ordered by the default x column (time). Numbers are finite JSON
  numbers; missing or non-finite samples are `null`, never zero.
- Full series, no truncation, sampling or interpolation. The largest
  (`CFIG-21291C1-sensors`, 35,370 rows × 20 columns) is about 6.8 MB of JSON;
  responses are serialized once and cached, since the data is frozen.
- No chart configuration is sent; the frontend maps rows to charts.

```sh
curl http://127.0.0.1:8000/api/v1/datasets/FLEX-1249-d2-fit/data
```

## Dataset CSV export (B05, optional)

`GET /api/v1/datasets/{dataset_id}/csv` is a download only, never the chart
transport. It is generated from the same prepared Parquet (UTF-8, comma,
header row equal to the descriptor's column keys, empty cell = null) and sent
as a `text/csv; charset=utf-8` attachment named `<dataset_id>.csv`, with
`Content-Disposition` exposed through CORS. Unknown IDs answer 404.

```sh
curl -OJ http://127.0.0.1:8000/api/v1/datasets/CFIG-21291C1-sensors/csv
```

## Describe a scenario (B06)

`POST /api/v1/filters/interpret` with `{"text": "..."}` returns
`{"filters": Filters, "warnings": string[], "mode": "live" | "demo", "searchable": boolean}`.
Every prompt starts with no filters; previous searches are not reused. The legacy
`current_filters` field is accepted for compatibility but ignored. If `searchable`
is true, send `filters` to the search endpoint; a valid search for all cases can
have empty filters. If it is false, show the warning and no results: do **not**
search the empty filters, which would otherwise return the entire catalogue.
`text` is trimmed, 1 to 4000 characters. Warnings are requested in English even
when the description is in Polish.

- **live** (default): one call to the selected Anthropic or OpenRouter model,
  with a JSON schema limited to the catalogue's categories. The full response
  is checked against the schema and the same filter rules as manual search;
  invalid or invented output answers 503 and changes nothing.
- **demo** (`PSI_AI_MODE=demo`): no network. Only the rehearsed prompts in
  `app/ai/interpret.py` (`DEMO_PROMPTS`) return reviewed filter states, always
  labelled `"mode": "demo"`; any other prompt returns `searchable: false` with
  a warning. A failed live call is never replaced by a demo answer.

Any assistant failure answers 503 with a readable `detail`; manual search keeps
working. Configuration errors, request failures and incomplete responses do not
trigger demo mode. Invalid `PSI_AI_MODE` or provider values also return 503.
When live settings are missing, `detail` names the required variables; it never
includes their values. For example:

```json
{"detail": "The AI assistant is not configured; set PSI_AI_MODEL, OPENROUTER_API_KEY in the server's .env or environment."}
```

### Live provider configuration

Copy `.env.example` to `.env` in the backend directory and edit the AI settings
there. The backend and offline PDF tool read that file automatically, regardless
of the working directory. Alternatively, set process environment variables;
those override `.env` values, including empty values. Changes to `.env` are read
on subsequent calls; restart the server after changing its environment. Use
literal values (variable expansion is not supported in the automatically read
file). Keep keys on the server, not in the frontend or API requests, and never
commit them. `.env` is git-ignored.

Choose one of the following examples for `.env` and replace the placeholder key:

```sh
# Anthropic
PSI_AI_MODE=live
PSI_AI_PROVIDER=anthropic
PSI_AI_MODEL=claude-opus-5-5
ANTHROPIC_API_KEY=your-anthropic-key
```

```sh
# OpenRouter
PSI_AI_MODE=live
PSI_AI_PROVIDER=openrouter
PSI_AI_MODEL=provider/model-name
OPENROUTER_API_KEY=your-openrouter-key
```

An explicit provider, model and matching key are required for live mode; there
is no model default in the code. Replace `provider/model-name` with an actual OpenRouter model that supports
structured JSON-schema output. The request requires an upstream supporting
the schema; unavailable models or incompatible providers return an error.
The same `PSI_AI_MODEL` variable is used by both providers, so update it when
switching. Anthropic's existing API-side refusal fallback to its default
fallback model remains enabled; this is not a demo response.

Each live request sends the supported-filter and unit rules, catalogue values
and bounds, an empty starting filter state, and user description to the selected provider.
OpenRouter may route the request to the chosen model's upstream provider. Review
their privacy and pricing terms before enabling live mode. Keys are not returned
to clients or logged by this backend; errors do not include provider response
bodies or exception messages.

For OpenRouter models that support reasoning effort, optionally set
`PSI_AI_REASONING_EFFORT` to `none`, `minimal`, `low`, `medium`, `high`,
`xhigh`, or `max`. Supported levels depend on the model. If omitted, OpenRouter
uses the model's default. Reasoning tokens may increase latency and cost.
This setting applies to OpenRouter only; the Anthropic adapter continues to use
the effort specified by the calling tool.

For a network-free rehearsal, use `PSI_AI_MODE=demo`; no model or key is needed.
The provider interface is independent of interpretation, so other adapters can
be added without changing the filter logic. Codex and Antigravity adapters are
not implemented; their intended API or CLI integration must be specified first.

## Demo walkthrough

```sh
python3 -m data_prep.prepare --data-dir ../data_nasa   # once
PSI_AI_MODE=demo python3 -m uvicorn app.main:app        # or live with ANTHROPIC_API_KEY
```

Reliable prompt (works in demo mode, also as plain filters in manual search):

> Pokaż testy z butanem powyżej 200 kPa i ponad 39% tlenu

It sets `fuel=butane`, `o2_pct>=39`, `pressure_kpa>=200` and returns six runs.
Cases worth showing:

- `CFIG-21291C1`: the source table records 5 hot-to-cool flame transitions in one run.
- `CFIG-21174C3` vs `CFIG-21174C2`: cool-flame run next to its hot-flame neighbour.
- `CFIG-21106F5`: direct cool flame with no hot ignition, at about 51 kPa.
- `CFIG-21162F1` vs `CFIG-21162C1`: no ignition at 20.7% O₂ against a burn at 21.0%.

Other rehearsed prompts: "Pokaż testy w atmosferze zbliżonej do ziemskiej:
20-22% tlenu, 95-105 kPa" (10 runs: 4 CFI-G, 6 FLEX) and "Pokaż testy przy
niskim ciśnieniu, 45-55 kPa" (9 runs); English versions are in `DEMO_PROMPTS`.

## Event annotations (B13)

`CaseDetail.events` lists entries copied from the ACME test-point script log
(`*_TP.txt`): "Ignition and retraction", "Extinction detected", "MFCs off".
Each has `label`, `time_s`, `dataset_id` (the dataset whose time axis it uses)
and `source` (the log file). The prepared artifact is `data/curated/events.json`.

- Method: `time_s` = log wall-clock time minus the clock time of the first
  sensor sample; the log has 1 s resolution, so markers are accurate to ~1 s.
- "Extinction detected" is the test script's own log entry. Nothing is
  detected or inferred here; blank log entries and cases without a log (all
  FLEX droplet cases) simply have no event, so there is no cross-run
  time-zero alignment.

## Droplet D² fit (B12)

One run, `FLEX-1249`, has an extra dataset `FLEX-1249-d2-fit` for a D²-law
chart: `time_s`, `D2_mm2` (droplet diameter squared) and `D2_fit_mm2` (the
fitted line, empty outside the fit window).

- Transform: D² = `DropletDiameter_mm`².
- Fit: ordinary least squares of D² against time over 4 to 36 s, a window
  chosen by hand in the manifest to cover the visually linear part. The
  burning-rate constant is K = minus the slope (D² = D0² - K·t).
- Result on the source data: K = 0.417 mm²/s, R² = 0.9998. The NASA summary PDF
  reports kavg = 0.426 mm²/s, computed by a method not documented in the
  files used here, so the two are shown side by side, not equated.
- No uncertainty band, no residual or predictive model, no fit for other runs.

## Nearest cases (B11)

`GET /api/v1/cases/{case_id}/neighbors` returns
`{"metric": string, "items": [{"case": CaseSummary, "distance": number}]}`:
up to 5 precomputed nearest cases, closest first (unknown case: 404). The
artifact `data/curated/neighbors.json` is rebuilt by the preparation script.

- Features: `o2_pct` and `pressure_kpa` only.
- Scaling: each feature standardised (zero mean, unit standard deviation)
  within the case's investigation; neighbours are never taken across
  investigations.
- Missing data: a case lacking either value (FLEX-1213) has no neighbours and
  is nobody's neighbour.
- Metric: Euclidean distance in that standardised plane, ties by case ID.

The distance only says how close the test conditions are. It is not a
calibrated similarity or a safety score, and no UMAP embedding is produced.

## Research-context tags (B14)

`CaseDetail.research_context` groups studies by fire-safety research context:
`tags` (any of `prevention`, `detection`, `suppression`, or `unknown`),
`rationale`, `evidence` (`document`, `page`, verbatim `quote`) and a
`disclaimer`. Tags are reviewed by hand per investigation in
`data_prep/research_context.json`; the script refuses a tag without evidence.

- `CFI (FLEX)`: `prevention`, backed by two quotes from the CFI overview
  presentation (cool flames can re-ignite; flammability boundaries).
- `ACME CFI-G`: `unknown`. The documents shipped with PSI-159 contain no
  statement tying it to prevention, detection or suppression.

The tags only group research context. They do not certify the fire-safety
performance of anything.

## Short case explanation (B15)

`CaseDetail.explanation` is `{"text": string, "origin": "template" | "curated" |
"generated"}` or `null`. All current explanations have origin `template`: one
or two plain sentences filled from the source table row (or, for FLEX, the
Master Sheet row and the reviewed summary-PDF values) by a fixed pattern in
the preparation script. No AI text is generated, and the explanation states
nothing the case's source fields do not. It is not a science chatbot.

## Two-pass preparation (B09)

`data_prep/two_pass.py` re-derives the filter values in two passes and checks
them against the curated catalogue:

```sh
python3 -m data_prep.two_pass propose  --data-dir ../data_nasa   # pass 1
python3 -m data_prep.two_pass classify --data-dir ../data_nasa   # pass 2
```

- Pass 1 reads every row of the two summary tables and writes
  `data_prep/vocabulary.proposed.json`: each raw fuel label with a suggested
  canonical value (plain names only; formulas and blends get `null`).
- A person reviews it and saves `data_prep/vocabulary.json` with
  `"reviewed": true`. The committed file has one manual decision
  (`C12H26` → `dodecane`, per the summary PDFs); the two blends stay `null`.
- Pass 2 revisits every test in the manifest, classifies the fuel through the
  reviewed vocabulary (unknown labels stay `null`), applies the same numeric
  rules as the main script, writes `data/curated/catalogue_two_pass.parquet`
  and exits non-zero unless it reproduces the curated filter values.

It currently reproduces all 43 curated cases. It is rule-based (no LLM), reads
metadata tables only (no research text or PDFs), and covers the selected
inputs, not the whole corpus.

## Offline PDF metadata enrichment (B08)

```sh
python3 -m data_prep.enrich_pdf FLEX-1213 "../data_nasa/CFI_PSI-39/pdf/FLEX-1213_Summary.pdf"
```

Reads one PDF page by page (`pdftotext`), asks the configured provider
(schema-constrained, same provider and model settings as the assistant) for parameters and timed events stated
explicitly for that one test, and writes
`data_prep/enrichment/<test>.proposed.json` for review. Needs
the selected provider's credentials; it is an explicitly invoked live tool and
does not use `PSI_AI_MODE=demo`.

- Every value needs a page number and a verbatim quote. The script, not the
  model, checks that the quote is on that page and contains the value;
  anything else lands in `rejected` with the reason.
- Fields that are not stated stay `null`. The prompt tells the model that
  campaign-wide statements, ranges and other tests' values are not values for
  this test.
- Differences from curated filter values are listed in
  `conflicts_with_curated`. Nothing is written to the catalogue or manifest; a
  person copies accepted values into `data_prep/manifest.json`.
- Scanned PDFs without a text layer are refused (no OCR).

This script has not been run against the live API in this repository (no key
on the build machine); its evidence checks are tested with a stubbed model and
on real PDF text.
